## Сборка и запуск

Нужны CMake, Ninja и компилятор с поддержкой C++17. Выполните команды
из корня репозитория.

Linux или macOS:

```sh
cmake -S homework_04 -B /tmp/fizkat-build -G Ninja
cmake --build /tmp/fizkat-build
/tmp/fizkat-build/fizkat
```

Windows, PowerShell с `g++`:

```powershell
cmake -S homework_04 -B "$env:TEMP/fizkat-build" -G Ninja -DCMAKE_CXX_COMPILER=g++
cmake --build "$env:TEMP/fizkat-build"
& "$env:TEMP/fizkat-build/fizkat.exe"
```

## Команды программы

Вводите по одной команде на строку. Номер `id` должен быть уникальным,
а номер и название `name` пишутся без пробелов. `energy` задаёт расход
в кВт·ч за сутки, `score` задаёт оценку от 1 до 10.

| Команда | Что делает |
| --- | --- |
| `add scooter id name energy score` | Добавляет электросамокат. |
| `add ebike id name energy score` | Добавляет электровелосипед. |
| `add bike id name score` | Добавляет обычный велосипед. |
| `add helmet id name` | Добавляет шлем. |
| `add dock id name energy` | Добавляет док-станцию. |
| `add pump id name` | Добавляет электрический насос с расходом 0.5 кВт·ч в сутки. |
| `list` | Печатает номера и названия, отсортированные по номеру. |
| `novice` | Показывает транспорт с оценкой от 6. |
| `count`, `count_novice` | Считает все позиции или только транспорт для новичков. |
| `energy` | Показывает суммарный расход энергии с одним знаком после запятой. |
| `focus id`, `show_focus` | Выбирает и показывает позицию на витрине. |
| `remove id` | Удаляет позицию из парка. |
| `quit` | Завершает работу программы. |

Например, после `add scooter S-1 ModelX 2.5 8` команда `energy` выведет
`2.5`. Если выполнить `focus S-1`, а затем `remove S-1`, команда
`show_focus` выведет `expired`.

## Наследование

Классы объявлены в [inventory.h](inventory.h). Стрелка `A -> B` означает,
что `B` наследуется от `A`.

```text
InventoryItem -> Item
Item -> Transport, Helmet
Transport -> Bike
Transport + EnergyConsumer -> ElectricTransport
ElectricTransport -> Scooter, ElectricBike
Item + EnergyConsumer -> Dock, Pump
```

`InventoryItem` и `EnergyConsumer` являются абстрактными базовыми классами.
Множественное наследование есть у `ElectricTransport`, `Dock` и `Pump`.
У их базовых классов нет общего предка, поэтому виртуальное наследование
не требуется. Парк обращается к объектам через `InventoryItem`.

## Умные указатели

- `unique_ptr` создаётся при разборе команды `add` в [main.cpp](main.cpp).
  До техосмотра у объекта один владелец. Если проверка не проходит, объект
  уничтожается автоматически.
- После успешной проверки [Fleet::add](fleet.cpp) передаёт объект в
  `vector<shared_ptr<InventoryItem>>`. Этот вектор хранит принятые позиции.
- Витрина в [Fleet](fleet.h) хранит `weak_ptr`, который не владеет объектом.
  После удаления позиции из парка витрина показывает `expired`.

## Исключения

Оба исключения наследуются от `FleetError` и обрабатываются в [main.cpp](main.cpp).

- `InspectionError` возникает, если в названии транспорта есть `broken`
  в любом регистре. Такой транспорт не добавляется в парк.
- `InputError` возникает при неизвестной команде, неверных аргументах,
  повторном номере или попытке выбрать либо удалить несуществующую позицию.

## Шаблон и операторы

`Total<T>` в [fleet.cpp](fleet.cpp) используется как `Total<double>` для суммы
энергии и как `Total<std::size_t>` для подсчёта техники для новичков.
В обоих случаях значение накапливается через `operator+=`.
`operator<<` печатает номер и название, а `operator<` сравнивает номера при сортировке.

## Креативная часть

Я добавил электрический насос `Pump`, чтобы на балансе было оборудование для обслуживания велосипедов. Его можно добавить командой `add pump P-1 Air`. Насос прибавляет 0.5 кВт/ч в сутки к общему расходу энергии, а в список прокатной техники не входит.

Я также добавил команду `count_novice`. Она показывает, сколько единиц транспорта с оценкой от 6 есть в парке. Это удобно, когда нужно узнать только количество техники для новичков без вывода всего списка.
